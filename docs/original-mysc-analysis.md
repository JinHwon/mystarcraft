# 원작 "마이스타크래프트" 분석

원작 게임 폴더(`D:\MYSC3\mysc`, 저장소 밖)를 분석한 결과다. 게임 파일은 저장소에 넣지 않았고, 이 문서에는 분석해서 뽑아낸 데이터와 구조만 정리했다.

- 분석 대상: `MyStarcraft.exe` (1,372,259 B, 2010-08-21), `img/` (GIF 368개), `save/` (세이브 6개)
- 방법: PE 헤더 파싱, 데이터 섹션 문자열 추출(CP949/UTF-16), 선수·맵 초기화 코드의 `push` 인자 해독, 세이브 파일 필드별 통계 비교, 일부 함수 기계어 직접 판독
- 신뢰도 표시: **확정**(코드나 데이터로 직접 확인), **추정**(정황 근거가 여럿 있음), **미확인**(값만 있고 의미는 모름)

## 2. 실행 파일 내부 데이터

### 2.1 선수 초기화 방식 (확정)

선수마다 아래 형태의 초기화 호출이 코드에 한 번씩 들어 있다 (230회).

```
push gender('M'=77 / 'F'=70)
push status            ; 1~4
push team              ; 0~12
push birthYear         ; 79~95 → 1979~1995년생
push stat[7] … stat[0] ; float, 350~950
push level             ; 1~10
push race              ; 1=T 2=Z 3=P
push name              ; "이제동     (Z)" (CP949, 종족 표시가 이름 문자열에 붙어 있음)
mov  ecx, [count]; imul ecx, 0B38h; add ecx, 542288h   ; players[count] (레코드 2,872 B)
call Player::Init
```

- 배열 크기 **300칸** (`cmp count, 12Ch`). 쓰는 칸은 230, 나머지는 빈 칸.
- 저장 값 = 초기값 **+ 816**. 능력치 getter는 `return stat[i] - 816`, 능력치 변경 함수는 더한 뒤 **[817, 1816]로 자른다**. 그래서 화면에 보이는 능력치 범위는 **1~1000**이다 (확정, 기계어 직접 판독).
- 선수 레코드 안의 `Player` 객체는 레코드 +36에서 시작한다: `+0 종족, +4 팀, +8~+36 능력치 8개(float)…`

### 2.2 능력치 8종과 저장 순서

| 슬롯 | 능력치 | 근거 | 신뢰도 |
|---:|---|---|---|
| 0 | 컨트롤 | 마우스 장착 시 가장 큰 보너스(+30/+60/+80)가 이 슬롯에 붙음 | 확정에 가까움 |
| 1 | 공격력 | 마우스 보조 보너스. 홍진호·박성준(투신)이 이 슬롯 최고치 | 추정 |
| 2 | 견제 | 마우스 보조 보너스. 김택용 950 | 추정 |
| 3 | 전략 | 강민(몽상가)·임요환이 이 슬롯 최고치 | 추정 |
| 4 | 물량 | 키보드 보너스. 도재욱 950, 최연성·임성춘 최고치 | 추정 |
| 5 | 수비력 | 키보드 보너스 (물량과 같은 값) | 추정 |
| 6 | 정찰 | 모니터만 낀 선수에게 이 슬롯에만 +80 (대형 LCD모니터 = 정찰+80) | 확정에 가까움 |
| 7 | 센스 | 남는 슬롯. 이제동 950, 이영호 900 | 추정 |

화면의 8각형 레이더 차트 라벨은 정찰→센스→컨트롤→수비력→공격력→물량→전략→견제 순서로 그려지는데, 이건 표시 배치일 뿐 저장 순서와 다르다. 저장소의 `STAT_KEYS` 8종(sense, control, attack, harass, strategy, supply, defense, scout)과 **이름이 정확히 일치**한다.

원작 exe에는 유닛 체력·공격력 같은 **유닛 스탯 표가 없다.** 경기는 유닛 단위로 계산하지 않고, 상황별 중계 문장으로 표현한다. 중계 멘트(약 1,000줄)에서 드러나는 빌드·전략 분류는 다음과 같다.

### 4.3 마이스타리그 (개인 리그, 실제 MSL 방식)

```
PC방 예선 토너먼트 (승자전/패자전)
  → 듀얼 토너먼트 (4인 조: 1경기·2경기 → 승자전·패자전 → 최종전, 2명 통과)
```

### 4.7 경기 시뮬레이션

코드를 끝까지 역컴파일하지는 않았다. 확인한 사실과 정황만 적는다.

- 입력: 두 선수의 능력치 8종 + 장비 보너스 + 컨디션, 맵(러시거리·자원·복잡도·종족 상성), 빌드
- 진행: 시간 흐름에 따라 빌드 선택 → 정찰 → 견제 → 교전 → 멀티/본진 파괴 → GG. 멘트 선택은 종족전·유닛 조합·유불리 상황별로 나뉜다.
- 결말 멘트가 경기 길이별로 따로 있다: 초반 승리(`초반에 손쉽게 승리`), 중후반 운영(`중후반 운영이 돋보이는`), 장기전(`엄청난 장기전 끝에`) → 게임 시간을 추적한다.
- 경기 후: 승자 세리머니(`승리의 댄스`, `관중석으로 돌진`, `카메라를 향해 윙크`), 치어풀 이벤트, 연승/연패 기록, 상대 전적 누적

### 5.2 이식할 만한 부분

우선순위 순.

1. **맵의 종족전별 상성값** (`TvZ / ZvP / PvT`, 100 = 균형)
   - 저장소는 종족마다 배율 하나라서 "테란이 저그에 강하고 토스에 약한 맵"을 표현하지 못한다.
   - `MapInfo.race`를 `{ tvz, zvp, pvt }`로 바꾸고, `mapAdvantage()`에서 `(값 - 100) / 1000` 정도로 완만하게 반영하면 된다. 원작 값 폭(80~140)을 그대로 쓰면 너무 세므로 절반 이하로 줄여서 쓰는 것을 권장.
   - 원작 맵 58개 중 저장소와 겹치는 맵(투혼, 매치포인트, 데스티네이션, 신백두대간, 블루스톰, 카트리나, 파이썬, 안드로메다, 네오메두사, 오델로, 비프로스트, 롱기누스, 아카디아, 몬티홀, 타우크로스, 루나, 러시아워, 레이드어썰트, 레퀴엠, 머큐리, 폴라리스랩소디, 청풍명월, 단장의능선)은 §2.4 수치를 참고값으로 쓸 수 있다.
2. **개인리그 MSL 방식**: 듀얼 토너먼트(4인 조, 승자전·패자전·최종전)와 조 지명식. 현재 16강 단판 토너먼트보다 이벤트성이 크고, `league.ts`의 세트 진행 함수를 그대로 재사용할 수 있다.
3. **프로리그 포스트시즌**: 정규시즌 순위 → 준플레이오프 → 플레이오프 → 결승. `PRO_SEASON_REWARD` 순위 보상과 함께 넣으면 시즌 마무리가 생긴다.
4. **엔트리의 히든 에이스**: 에이스 결정전 출전자를 미리 공개하지 않는 방식. AI 팀 엔트리 선택에도 쓸 수 있다.
5. **경기 전 소모품**: `스나이핑`(상대 예측 성공 시 한 경기 능력치 보너스), `츄잉껌`(패배 시 능력치 하락 완화), `세레모니`(승리 시 골드), 승리 시 팀 전원 컨디션 +1 아이템. 기존 아이템 테이블에 "1경기 효과" 타입만 추가하면 된다.
6. **장비 내구도**: 이미 `usageCount`가 있으니, 원작처럼 슬롯(마우스/키보드/모니터/기타)을 나누고 슬롯별 1개만 장착하게 하면 조합 고민이 생긴다.
7. **경기 길이별 결말 멘트와 승리 세리머니**: `bwEngine`의 `endReason` + `gs.time`으로 초반/중반/장기전 결말 문장을 고르면 된다. 문장은 원작을 옮기지 말고 새로 쓰는 것을 권장.
8. **선수 레벨·나이·성별 메타데이터**: 레벨이 시즌마다 오르는 구조, 나이에 따른 성장/하락 곡선 등은 장기 플레이 요소로 쓸 수 있다.

### 5.3 옮기지 않는 게 나은 부분

- **능력치 +816 오프셋 저장 방식**: 원작의 구현 사정일 뿐이다. 저장소처럼 표시값 그대로 저장하는 편이 낫다.
- **유닛 없는 멘트 추첨식 경기 진행**: 저장소 `bwEngine`이 훨씬 정교하다. 원작에서는 멘트 분류(종족전 × 유닛 조합 × 유불리)만 참고한다.
- **실존 선수 이름·사진, 원작 중계 문장**: 초상권·저작권 문제가 있으니 데이터 구조와 분포(능력치 범위, 레벨 분포, 팀 구성비)만 참고한다.
- **포션의 랜덤 ± 효과**: 모바일 과금·보상 구조에서는 불만 요소가 되기 쉽다.

5. 스탯 getter(`fsub [816]`)와 clamp 함수(`fcomp 817 / 1816`)는 기계어를 직접 읽어 확인
